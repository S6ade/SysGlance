## Этап 0: Подготовка
**Цель:** создать базовую структуру и окружение.
**Критерии готовности:**
- [✅] Репозиторий `sysglance` на GitHub создан.
- [✅] Локальная копия (git clone) есть.
- [✅] Виртуальное окружение Python активировано.
- [✅] `psutil` установлен.
- [❌] Структура папок соответствует плану.
- [✅] Описание `README.md`.

**Зависимости:** нет.

---

## Этап 1: Скрипты диагностики
**Цель:** реализовать отдельные проверки и единый сборщик.
**Критерии готовности:**
- [✅] Все скрипты (`check_quick.py`, `check_resources.py`, …, `check_full.py`) работают локально.
- [✅] Флаг `--json` реализован во всех скриптах.
- [✅] Обработка ошибок: при отсутствии доступа скрипт не падает, возвращает `null` или предупреждение.
- [ ] Тесты (минимум smoke) для каждого скрипта.

**Зависимости:** Этап 0.

---

## Этап 2: CLI (Typer)
**Цель:** удобный интерфейс командной строки.
**Критерии готовности:**
- [ ] `typer` установлен, `cli/main.py` создан.
- [ ] Команды `sysglance quick`, `full`, `resources`, `security`, `logs`, `network`, `services` работают.
- [ ] Флаги `--json`, `--help` реализованы.
- [ ] Проект собирается через `pyproject.toml` или `setup.py`.
- [ ] После `pip install .` команда `sysglance` доступна в терминале.

**Зависимости:** Этап 1.

---

## Этап 3: API (FastAPI)
**Цель:** HTTP‑интерфейс для проверок и авторизации.
**Критерии готовности:**
- [ ] Установлены `fastapi`, `uvicorn`.
- [ ] Эндпоинты `/` и `/health` возвращают корректные ответы.
- [ ] Реализованы эндпоинты для всех типов проверок.
- [ ] **Авторизация (JWT)**: регистрация и логин пользователя.
- [ ] **Авторизация (API‑ключ)**: проверка API‑ключа для агента (отдельный механизм).
- [ ] Swagger‑документация (`/docs`) доступна и содержит описания.

**Зависимости:** Этап 1, Этап 2 (логика проверок).

---

## Этап 4: Агент
**Цель:** агент для отправки отчётов с серверов.
**Критерии готовности:**
- [ ] Пакет `sysglance-agent` подготовлен к публикации.
- [ ] Команды `run`, `register`, `status` работают.
- [ ] Конфигурация хранится в `~/.sysglance/config.yml`.
- [ ] Агент умеет отправлять отчёты на API.

**Зависимости:** Этап 3.

---

## Этап 5: База данных + пользователи
**Цель:** хранение пользователей, серверов, ключей, отчётов.
**Критерии готовности:**
- [ ] PostgreSQL установлен и база `sysglance` создана.
- [ ] Модели `User`, `Server`, `ApiKey`, `Check` описаны.
- [ ] Миграции (Alembic) работают, таблицы создаются автоматически.
- [ ] CRUD для пользователей и серверов реализован.
- [ ] **Резервное копирование БД настроено** (для продакшена).

**Зависимости:** Этап 3.

---

## Этап 6: Web‑интерфейс (React)
**Цель:** дашборд и управление серверами.
**Критерии готовности:**
- [ ] Базовый каркас с роутингом и авторизацией (JWT).
- [ ] Дашборд: список серверов, цветовые индикаторы, сводка.
- [ ] Страница сервера: выбор проверки, отображение отчёта, история.
- [ ] Страницы профиля, API‑ключей, серверов.

**Зависимости:** Этап 3, Этап 5.

---

## Этап 7: AI‑агент
**Цель:** анализ отчётов и рекомендации.
**Критерии готовности:**
- [ ] Интеграция с LLM (Ollama / OpenAI).
- [ ] Кнопка «Спросить AI» и передача JSON‑отчёта.
- [ ] Промпт настроен, рекомендации осмысленные.
- [ ] Безопасность: никакие секреты не уходят в LLM.

**Зависимости:** Этап 3, Этап 6.

---

## Этап 8: PWA (мобильная версия)
**Цель:** работа с дашбордом с телефона.
**Критерии готовности:**
- [ ] `manifest.json`, Service Worker, иконки готовы.
- [ ] Push‑уведомления работают.
- [ ] Адаптивный дизайн: кнопки удобно нажимать пальцем.

**Зависимости:** Этап 6.

---

## Этап 9: Деплой
**Цель:** готовый к эксплуатации стек.
**Критерии готовности:**
- [ ] Dockerfile для API, Web.
- [ ] `docker-compose.yml` (API + Web + PostgreSQL).
- [ ] Nginx reverse proxy настроен.
- [ ] GitHub Actions CI/CD настроен.
- [ ] HTTPS (Let’s Encrypt) работает.
- [ ] **Мониторинг самого SysGlance** (health‑check, чтобы знать, что платформа жива).

**Зависимости:** Все предыдущие этапы.
